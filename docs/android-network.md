# Android 网络与悬浮窗修复（1.1.1）

## 为什么旧版不用代理也能使用

原 1.0 版使用 `data-api.binance.vision/api/v3` 和 `data-stream.binance.vision`，均为现货行情。按照项目要求切换到 USDⓈ-M 合约后，入口变为 `fapi.binance.com/fapi/v1` 和 `fstream.binance.com/market/stream`。不同域名在同一运营商网络中的解析和连接情况可能不同；旧入口能访问，不代表新入口也能访问。

2026-11-20 在本机关闭代理的测试中：旧 `.vision` ping 成功，新 `fapi.binance.com` 连接超时；经 HTTPS DNS 查询，主机的系统 DNS 曾将新域名解析到了无关地址。修正地址后主域名仍发生连接重置，因此不能仅靠更新合约列表或增加域名重试解决。

## 新版如何自动连接

1. 默认请求币安官方合约 API。
2. 主域名连接失败时，查询它当前的官方 CDN 分发地址，并通过该地址请求同一合约 API。
3. 只接受币安合约主机对应的 CloudFront CNAME，正常验证 HTTPS 证书，保留原始主机请求头；不写死 CDN，不引入其他交易所价格。
4. 成功的通道短期缓存；WebSocket 不通时，每 5 秒使用 REST 获取合约行情。每个合约仅有一个在途请求，停止或切换自选时取消旧请求。

本机普通网络通过这一路径已取到合约列表（包含 MUUSDT、SNDKUSDT、SKHYNIXUSDT）、24 小时行情及 K 线。手机运营商、地区、DNS 服务和币安 CDN 配置仍可能不同，需要在目标手机安装确认；不保证所有网络始终可达。

## 如果仍然失败

点击「刷新」会重新连接行情并刷新合约列表。状态区可区分域名错误、安全连接失败、HTTP 限流或访问限制，价格栏使用短提示，避免长错误信息撑开布局。

「网络」默认为自动连接，代理是可选项：可以使用已覆盖 FloatBit 的手机 VPN，或填写自己的 HTTP 代理。若使用同一 Wi-Fi 下电脑的代理，应填写电脑的局域网 IP，代理需允许局域网访问；手机里的 `127.0.0.1` 指手机自身。保存后，列表、行情、K 线和悬浮窗立即使用新配置；选择「自动连接」可清除该配置。

GitHub Pages 仅发布静态官网和安装包，不承担实时行情中转。

## 悬浮窗尺寸

移除新增的 280dp 面板固定宽度，恢复 `wrap_content`；币种栏从 72dp 恢复旧版 40dp。保留长名称单行缩放/省略、原有行距、字体、缩小与边缘收起行为。价格和涨跌幅保持单行，网络错误不会增加浮窗高度。

## 验证

构建命令：`./gradlew testDebugUnitTest assembleDebug --no-daemon`。

单元测试覆盖合约 URL 路径、自动备用通道、原始 Host 请求头、CNAME 校验、请求取消、超时回调、限流与无效合约、HTTP 代理对 REST 和 WebSocket 的路由。真实网络检查保持 HTTPS 证书校验，并显式禁用系统与环境代理；未使用现货接口作为合约兜底。
